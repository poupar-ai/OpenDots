## Bugs arquiteturais resolvidos

### Path divergente: writer vs reader (raiz dos commits 6, 7, 10)

Hooks (`session_init`, `observe`, `session_end`), seeds applier e MCP server **sempre**
gravavam em `<project_root>/.claude-project-memory/`. Mas `bin/http.rs` derivava
`AppState.mem_dir` de `mem_dir_base` (clone do plugin, via `find_project_root(cwd)`).

Sintomas em cascata:
- Agentes instalados pela UI não apareciam no `/api/data` (apareciam como `null`)
- `POST /api/chat` retornava `{"error":"agent X not found"}` mesmo após install com sucesso
- `make uninstall` deixava arquivos órfãos no path "errado"

Fix: `mem_dir = project_root.join(MEM_DIR_NAME)`. `scope.json` continua sendo lido do
path legado (binary-local) só pro bootstrap saber qual é o `project_root`.

### Config de processo misturada com dados de projeto (commit 7)

`network.json` (bind = localhost/lan/custom) é config de **processo**, não dado de
projeto. Misturar no `mem_dir` project-scoped quebrava binding quando o user trocava
`project_root` via UI.

Fix: `AppState.runtime_cfg_dir` (binary-local), separado de `mem_dir`. Seed startup
script continua escrevendo `network.json` lá e o pmem-http lê do mesmo lugar.

### Sandbox `simple_expansion` do Claude Code (commits 8, 9, 10)

Agentes spawnados pelo pmem-http tinham instruções pra fazer handoff via curl com
`-H "Authorization: Bearer $PROJECT_MEM_AGENT_TOKEN"`. Mas a regra `simple_expansion`
do Claude Code rejeita **qualquer** comando Bash com `$VAR` na linha — anterior ao
match de allowlist. Confirmado via `claude-code-guide`: não há permission/hook/setting
que libere isso.

Fix em 3 camadas:
1. **Wrapper `pmem`** (`plugin/agent-bin/pmem`, bash) lê o token do env internamente.
   Agente vê apenas `pmem handoff oracle "msg"` no comando — sem `$VAR`.
2. **PATH injection** em `agent_runner.rs` e `chat_send_routes.rs`: `<plugin_dir>/agent-bin`
   na frente do PATH herdado, mais `PROJECT_MEM_PORT` no env.
3. **Auto-provisioning de keypair**: `mint_token_for` agora cria keypair Ed25519 no
   filesystem (`<mem_dir>/agent_keys/<NAME>.priv`, perms 0600) se não existir, e grava
   pubkey hex no `agents.json`. Vault deixou de gatear identidade de agente — continua
   existindo só pra secrets do usuário.

## Decisão de padrão: agentskills.io

Adotado **só pra camada de skills** (`plugin/skills/<slug>/SKILL.md` com frontmatter
YAML). Open standard da Anthropic (dez/25), adotado por Codex, Cursor, Copilot, Gemini
CLI, Junie, Goose, Cline, etc. — skills viram portáveis.

**Não estender pra outras camadas**: `agents.json`, `.mcp.json`, JWT Ed25519, queue,
runtime de handoff seguem proprietários. agentskills.io não cobre essas e ainda não há
padrão aberto consolidado pra inter-agent communication.
