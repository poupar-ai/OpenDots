claude-project-memory

A Claude Code plugin that keeps persistent, git-committable memory per project — stored as plain text inside the repository itself. No database, no external services, no background processes.

GitHub MIT License ♥ Sponsor
⚠ Under active development — functional but evolving. Open an issue if you find a problem.

Overview

Every time you open Claude Code it starts from scratch — no memory of previous sessions, no awareness of project conventions, no context about decisions made and why.

claude-project-memory fixes this by maintaining a live context per project and injecting it automatically at the start of each conversation.

  1. Open Claude Code — a status banner confirms the plugin is active
  2. Type your first message
  3. Claude already receives: PROJECT.md + recent session summaries + prior observations + detected patterns
  4. Each file edit and command is silently recorded in the background
  5. When the session ends, a summary is generated automatically

Installation

Via Claude Code (recommended)

Open Claude Code and ask:

Install the plugin schedylabs/claude-project-memory

Or run directly in the terminal:

claude plugins marketplace add schedylabs/claude-project-memory
claude plugins install project-mem@project-mem

Restart Claude Code. That's it.

Manual

Requirements: Claude Code and Node.js.

git clone git@github.com:schedylabs/claude-project-memory.git
cd claude-project-memory
make install
make status     # check installation
make uninstall  # remove the plugin

How memory is stored

Memory lives inside each project under .claude-project-memory/:

my-project/
├── .claude/
│   └── CLAUDE.md                  ← auto-synced from PROJECT.md (native Claude read)
└── .claude-project-memory/
    ├── PROJECT.md          ← permanent context (stack, patterns, decisions)
    ├── config.json         ← project metadata and settings
    ├── sessions.jsonl      ← session history with summaries
    ├── observations.jsonl  ← recorded file edits and commands
    ├── graph.json          ← detected pattern graph
    ├── stats.json          ← counter cache (used by the status banner)
    └── tmp/                ← per-session flag files

Dual context delivery

Context reaches Claude through two parallel mechanisms for maximum reliability:

MechanismWhenWhat it injects
.claude/CLAUDE.md (native)Every session, before any hookFull PROJECT.md as system prompt
Hook UserPromptSubmitFirst prompt of the sessionRecent sessions + observations + graph

.claude/CLAUDE.md is auto-synced from PROJECT.md every session. Claude reads it as part of the system prompt — no hook dependency required.

Why JSONL?

PropertyBenefit
git diffShows exactly what changed in memory between commits
git blameShows when each piece of information was added
Plain textAny editor, any tool — grep, jq, cat
No binaryZero dependency on SQLite or any database

Committing .claude-project-memory/ is optional — but if you do, every developer who clones the repo gets the full project context immediately.

Pattern graph

Beyond raw observations, the plugin maintains a graph.json that grows with usage and surfaces patterns automatically. These are injected as additional context at session start.

PatternWhat it detects
Hot filesFiles you edit most frequently
CouplingFiles edited together in the same session
WorkflowsRecurring sequences of "edit file X → run command Y"

Example of what Claude sees at session start:

## Detected patterns

### Most active files
- `src/auth.py` — 14x
- `tests/test_auth.py` — 11x

### Couplings (edited together)
- `auth.py` ↔ `test_auth.py` (9x)

### Detected workflows (edit → run)
- edit `auth.py` → `pytest tests/ -v` (7x)

/mem-setup

Analyzes the project in depth and creates .claude-project-memory/PROJECT.md.

  1. Reads dependency manifests, configs, folder structure, and code samples
  2. Presents a diagnosis: stack, architecture, identified conventions, how to run
  3. Asks the developer for context not visible in the code (constraints, decisions, pitfalls)
  4. Creates .claude-project-memory/PROJECT.md with everything documented

From that point on, Claude never forgets the project's patterns.

/mem-search

Full-text search across the entire memory history.

/mem-search authentication
/mem-search pytest
/mem-search "database migration"
/mem-search file: models.py
/mem-search bash: docker
/mem-search session: refactor

Prefix filters: file:, bash:, session: — no prefix searches everything.

Comparison with claude-mem

claude-memclaude-project-memory
Storage location~/.claude-project-memory/ (global).claude-project-memory/ (per project)
FormatSQLite + Chroma (binary)JSONL (plain text)
GitNot directly committableDesigned to commit and share
RuntimeBun worker processDirect Node.js scripts
DependenciesBun, tree-sitter, SQLite, ChromaNode.js only
SearchSemantic via embeddingsFull-text + pattern graph
Team sharingPersonal per developerShared via git

Both can coexist — they serve different purposes.
